# MT5 トラブルシューティング

**WolfBot Community v0.1.0-beta.4 でテスト済み** · 最終更新: 2026-08-18

## このガイドの対象者

- **MT5 を WolfBot Community に接続する際にエラーに遭遇した方** — 以下の修正を順番に試してください。それぞれ推測ではなく、自分で読めるログを指し示します。
- **技術的な背景のある方** — どのコンポーネントが何をログ出力するかを根本原因のセクションで正確に説明するので、自分のマシンで診断できます。

## 始める前に

以下の2つのクイックチェックだけで、多くの MT5 接続問題が他の何よりも早く解決します:

1. **デモ vs 実口座。** 接続ガイドと同様に、まず **デモ(テストネット)** の MT5 口座を接続していることを確認してください。実口座は準備チェックに失敗することがあり(テスト対象としてもリスクが高くなります)。
2. **MT5 ブリッジは Linux インストールの一部のみです。** MT5 は Linux 上のコンテナ内で動作します(1コマンドで有効化)— まだリリースされていない Windows ビルドには同じ形では同梱されていません。従っているガイドと自分のプラットフォームが一致しているか確認してください。

## よくあるエラーと確認事項

### 「Could not set up the MT5 account. Please try again.」(`MT5_PROVISIONING_FAILED`)

これは実運用インストールから報告される主なエラーです。MT5 ターミナル/ブリッジの**アカウントごとのプロビジョニングステップ**が完了できないときに発生します。まず API 認証情報を変更する前に、以下を順番に確認してください:

1. **control/api のログを読む。** プロビジョニングの試行と、それが返した正確な失敗内容を確認します。ターミナル/ブリッジコンテナが作成できなかった場合、メッセージには `container_provisioned=false` が記録されます。
2. **コンテナランタイムに到達できることを確認する。** Community インストールでは、ブリッジコントロールへの Docker ソケットマウントが欠けていると、アカウントごとのコンテナが作成できなくなります — これが多くの `MT5_PROVISIONING_FAILED` エラーの構造的な原因です。ログにソケット/権限エラーが表示されている場合、それがボトルネックです。
3. **ブリッジイメージが存在することを確認する。** MT5 ブリッジイメージが pull されていない場合、他がすべて正常であってもプロビジョニングはイメージ未検出エラーで失敗します。
4. **ログを確認した後に再試行する。** これは「キーを削除して再追加する」ような状況ではありません。状態はプロビジョニングステップにあり、ログが実際の失敗内容を教えてくれます。

### 口座は接続できるがシンボルが表示されない

- 戦略が参照しているシンボルが対象取引所へのマッピングを持たない場合、WolfBot はそれをそのまま素通しします。正確なシンボル表記を確認し、[シンボルマッピングガイド](/docs/mt5-symbol-mapping)を確認してください。
- シンボルリストが空に見える場合、MT5 口座の選択済みシンボルファイルを確認し、MT5 のマーケットウォッチに実際にその銘柄が読み込まれているか確認してください。

### 起動直後に接続が切れる、または注文エラーが出る

- テスト中に typo や不正な銘柄が誤って実ポジションを開かないよう、まず戦略が **シミュレーション** に設定されていることを確認してください。
- ターミナルの状態を MT5 ブリッジログで確認してください。ブローカーにまだログインしていないヘッドレスターミナルは、セッションが確立されるまで注文を拒否します。

### まだ解決しない場合

確実な答えを得る最も速い方法は、ログを目の前にして正確なエラーを再現することです:

- **Control/api のログ** — プロビジョニングと口座の準備状態(実際に何が失敗しているか)。
- **MT5 ブリッジのログ** — ターミナルのログインと注文の状態。

サポートスレッドを開くときは、`MT5_PROVISIONING_FAILED` のような具体的なエラー行と、対応するログフレームを貼り付けてください — それが何往復もするやり取りではなく一発で解決できるかどうかの分かれ目です。
