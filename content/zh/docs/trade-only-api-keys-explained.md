# 仅限交易 API 密钥详解

**已在 WolfBot Community v0.1.0-beta.9 上测试** · 最后更新: 2026-08-15

## 本指南适合谁

- **如果你想连接交易所却不想让资金承担风险** —— 本文用通俗的语言告诉你,哪一项权限永远应该关闭,这样即使密钥泄露,你的账户也不会被清空。
- **如果你比较偏技术型** —— 你会了解确切的权限模型(读取/交易 对比 提现/划转),以及作为第二层保障的 IP 限制。

## 最重要的一项设置

每个交易所都允许你创建一个附带特定权限组合的 API 密钥——而不是"你的整个账户",而是其中更窄的一个切片。当你将交易所连接到任何交易机器人(包括 WolfBot)时,你做出的最重要的一个决定,就是这个密钥拥有哪些权限。

WolfBot 始终只需要两项权限:

- **读取** —— 查看你的余额、挂单和持仓
- **交易** —— 下单和撤单

它绝不需要、也绝不应该被授予:

- ❌ **提现** —— 将资金转出交易所
- ❌ **划转** —— 在交易所子账户之间或转给其他用户

## 如果你依然开启了提现权限会怎样

大多数时候什么都不会发生——直到真正出事的那一次。如果你的 API 密钥或存放它的机器一旦被攻破,损失的范围完全取决于该密钥*被允许*做什么,而不是你的机器人实际用到了什么。一个落入坏人之手的仅限交易密钥,最多只能下一些你不想要的订单——虽然烦人,但你能发现并撤销。而一个开启了提现权限的密钥落入坏人之手,则可能清空整个账户。

这正是为什么交易所会把这项权限设计成一个独立于交易权限之外的复选框——它就是为了让你在这种场景下能单独关闭它。

## 为什么这一点对自托管工具尤其重要

WolfBot Community 运行在你自己的机器上——这本身就是一项真正的安全优势(参见[自托管详解](/docs/self-hosted-explained)),但这也意味着 API 密钥存放在你自己的环境中,而不是在某个供应商加固过的基础设施背后。仅限交易权限正是让这种权衡变得无关紧要的关键:即使你的机器被攻破,拿到你 API 密钥的攻击者依然无法把你的资金转移到任何地方,因为交易所本身就会拒绝该密钥发起的提现请求。

这也是为什么 WolfBot 是**非托管的**——WolfBot 或任何其他人,在任何时候都不会持有你的资金。资金始终留在交易所,受你自己控制的权限保护,你也可以随时在自己的交易所账户中立即撤销该密钥。

## IP 限制 —— 第二层保障

大多数交易所还允许你将 API 密钥锁定到特定的 IP 地址。如果你在固定的家庭网络或 VPS 上运行 WolfBot,这会增加一道独立的屏障:即使一个仅限交易的密钥泄露了,在其他任何地方也无法使用它。并非每个交易所在每个账户等级都支持这项功能,但只要有提供,就值得开启。

## 每个你连接的经纪商都应检查的清单

- [ ] 交易权限:**已启用**
- [ ] 读取权限:**已启用**
- [ ] 提现权限:**已关闭**
- [ ] 划转权限:**已关闭**
- [ ] IP 限制:**在支持的情况下已启用**
