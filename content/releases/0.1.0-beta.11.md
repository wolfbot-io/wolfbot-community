# WolfBot Community v0.1.0-beta.11

**Tested with WolfBot Community v0.1.0-beta.11** · Last updated: 2026-09-25

WolfBot Community v0.1.0-beta.11 is the latest public release of the free, self-hosted WolfBot trading platform. This release restores Live Translate (missing from v0.1.0-beta.10's installer) and improves error clarity for self-serve MT5 setup on Docker.

**Live Translate is back.** v0.1.0-beta.10's signed installer accidentally omitted the Live Translate service image. This release's signed manifest includes the full translator image set again, so a fresh v0.1.0-beta.11 install has Live Translate available out of the box.

**No new Windows build in this release.** v0.1.0-beta.11 ships Linux only. If you're on Windows, keep using the [v0.1.0-beta.10](/releases/0.1.0-beta.10) installer for now (same known market-data-reconnect issue as before); a corrected, code-signed Windows build will follow in an upcoming release.

## What is new since v0.1.0-beta.10

### Live Translate is restored

v0.1.0-beta.10's signed release manifest omitted the Live Translate service image, so the `/translate` proxy returned an error on that installer even though the feature is fully implemented in the codebase. This was a packaging gap, not a code defect. v0.1.0-beta.11's signed manifest includes the translator image set again — a fresh install has real-time speech and text translation across 52 languages available immediately, and captions/dubbing for any browser tab (video calls, YouTube, livestreams, and more) work as documented.

Learn more: [Live Translate — Break the Language Barrier with Local AI](/tools/live-translate).

### Clearer errors for self-serve MT5 setup when Docker isn't reachable

Self-serve MT5 account setup now classifies a Docker-unreachable condition as its own distinct error, instead of surfacing it as a generic provisioning failure. You get a clear, specific message telling you Docker itself couldn't be reached, so you know to check your local Docker installation rather than assume the MT5 broker connection is the problem.

## Highlights carried over from previous releases

### TradingView webhook automation

TradingView alerts flow through the real WolfBot command pipeline.

| TradingView payload action | WolfBot behavior |
|---|---|
| `buy` | queue/open long |
| `sell` | queue/open short |
| `close_long` | close an existing long side |
| `close_short` | close an existing short side |

The webhook route validates the source secret, deduplicates repeated signals, writes an internal command, and then lets the normal dispatcher, execution layer and risk controls handle the action. TradingView does not receive exchange API keys and does not talk to exchanges directly.

Start here: [TradingView Webhook to WolfBot Community](/docs/tradingview).

### One platform for crypto, futures and MT5

WolfBot Community continues to target one interface for:

- Binance
- Bybit
- BingX
- KuCoin
- Bitget
- MT5 brokers for Forex, Gold, Indices and broker-dependent CFDs

Use Simulation or broker demo accounts first. Move to live accounts only after verifying your setup and risk controls.

### Digest-pinned, signed runtime images

The release manifest pins the runtime by immutable container image digests, including the restored translator tiers. The installer pulls the exact image set signed for this release, not a mutable tag that can drift later.

Use v0.1.0-beta.11 if you want to:

## Security model

WolfBot Community is designed to be self-hosted and non-custodial:

- your API keys stay on your machine;
- use trade-only API keys;
- withdrawal and transfer permissions should remain disabled;
- installers publish SHA256 checksums;
- runtime images are digest-pinned and cryptographically signed;
- TradingView alerts use a WolfBot source secret and never contain broker credentials;
- Live Translate runs entirely locally — no audio or text leaves your machine.

## Recommended first-run path

WolfBot Community is trading infrastructure, so the best first install flow is practical and controlled:

- Install the signed Linux `.deb` or `.run` package from this release.
- Open the local setup wizard at `http://127.0.0.1:8080/portal/local/setup`.
- Start with Simulation or a broker demo account to learn the workflow.
- Use trade-only API keys for live exchanges and keep withdrawal permissions disabled.

- On Windows, keep using the v0.1.0-beta.10 installer until a corrected, code-signed build ships.
