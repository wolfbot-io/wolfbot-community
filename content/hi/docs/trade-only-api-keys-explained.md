# ट्रेड-ओनली API कुंजियां समझाई गईं

**टेस्ट किया गया संस्करण: WolfBot Community v0.1.0-beta.4** · आखिरी अपडेट: 2026-08-15

## यह गाइड किसके लिए है

- **अगर आप अपने फंड को जोखिम में डाले बिना एक एक्सचेंज कनेक्ट करना चाहते हैं** — यह आपको सरल भाषा में वह एक अनुमति दिखाता है जिसे हमेशा बंद रखना चाहिए, ताकि लीक हुई कुंजी कभी भी आपका अकाउंट खाली न कर सके।
- **अगर आप तकनीकी रूप से इच्छुक हैं** — आपको सटीक अनुमति मॉडल (Read/Trade बनाम Withdraw/Transfer) और IP प्रतिबंध की दूसरी परत मिलेगी।

## सबसे ज़्यादा मायने रखने वाली एक सेटिंग

हर एक्सचेंज आपको एक ऐसी API कुंजी बनाने देता है जिसके साथ एक तय अनुमतियों का सेट जुड़ा हो — "आपका पूरा अकाउंट" नहीं, बल्कि उसका एक संकरा हिस्सा। जब आप किसी भी ट्रेडिंग बॉट से एक एक्सचेंज कनेक्ट करते हैं, WolfBot समेत, सबसे ज़्यादा मायने रखने वाला फ़ैसला यह है कि उस कुंजी के पास कौन सी अनुमतियां हैं।

WolfBot को कभी सिर्फ़ दो की ज़रूरत होती है:

- **Read** — अपना बैलेंस, खुले ऑर्डर और पोज़िशन देखें
- **Trade** — ऑर्डर लगाएं और रद्द करें

इसे कभी ज़रूरत नहीं होती, और कभी नहीं दी जानी चाहिए:

- ❌ **Withdraw** — एक्सचेंज से फंड बाहर ले जाना
- ❌ **Transfer** — एक्सचेंज सब-अकाउंट के बीच या दूसरे यूज़र को फंड भेजना

## अगर आप विड्रॉल फिर भी सक्षम रखें तो क्या होता है

ज़्यादातर समय कुछ नहीं होता — जब तक वह एक बार न आए जब यह मायने रखे। अगर आपकी API कुंजी या जिस मशीन पर यह स्टोर है वह कभी समझौते में आती है, तो नुकसान की सीमा पूरी तरह इस बात से तय होती है कि वह कुंजी क्या *कर सकती है*, न कि आपका बॉट असल में क्या इस्तेमाल करता है। गलत हाथों में एक ट्रेड-ओनली कुंजी अनचाहे ट्रेड लगा सकती है — तंग करने वाला, और ऐसा कुछ जिसे आप नोटिस करके पलट सकते हैं। गलत हाथों में एक विड्रॉल-सक्षम कुंजी अकाउंट खाली कर सकती है।

यही वजह है कि एक्सचेंज इस अनुमति को ट्रेडिंग से अलग अपना खुद का चेकबॉक्स देते हैं: यह ठीक इसी इस्तेमाल के लिए बंद किए जाने के लिए है।

## सेल्फ-होस्टेड टूल के लिए यह ज़्यादा क्यों मायने रखता है

WolfBot Community आपकी अपनी मशीन पर चलता है — जो एक असली सुरक्षा फ़ायदा है (देखें [सेल्फ-होस्टेड समझाया गया](/docs/self-hosted-explained)), लेकिन इसका मतलब यह भी है कि API कुंजी आपके एनवायरनमेंट में रहती है, किसी वेंडर के अपने हार्डन इंफ्रास्ट्रक्चर के पीछे नहीं। ट्रेड-ओनली अनुमतियां ही इस ट्रेड-ऑफ़ को गैर-मुद्दा बनाती हैं: भले ही आपकी मशीन समझौते में आ जाए, आपकी API कुंजी रखने वाला हमलावर फिर भी आपका फंड कहीं नहीं ले जा सकता, क्योंकि एक्सचेंज खुद उस कुंजी से आए विड्रॉल अनुरोध को अस्वीकार कर देता है।

यही वजह है कि WolfBot **नॉन-कस्टोडियल** है — WolfBot, या कोई और, कभी भी आपके फंड को होल्ड नहीं करता। ये एक्सचेंज पर रहते हैं, आपकी नियंत्रित अनुमतियों के तहत, और आप कभी भी अपने एक्सचेंज अकाउंट से कुंजी को तुरंत रद्द कर सकते हैं।

## IP प्रतिबंध — दूसरी परत

ज़्यादातर एक्सचेंज आपको एक API कुंजी को किसी खास IP पते से लॉक करने भी देते हैं। अगर आप WolfBot को एक फ़िक्स्ड होम कनेक्शन या VPS पर चला रहे हैं, तो यह एक दूसरी स्वतंत्र बाधा जोड़ता है: ट्रेड-ओनली अनुमतियों वाली लीक हुई कुंजी भी कहीं और से बेकार हो जाती है। हर एक्सचेंज हर अकाउंट टियर पर इसे सपोर्ट नहीं करता, लेकिन जहां भी यह मिले, इसे सक्षम करना उचित है।
