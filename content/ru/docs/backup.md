# Гайд по резервному копированию и восстановлению

**Протестировано с WolfBot Community v0.1.0-p12-ghcr-rc8** · Последнее обновление: 2026-08-15

## Зачем резервное копирование?

WolfBot хранит вашу конфигурацию локально: подключения API брокеров, настройки стратегий, параметры риска, конфигурации ботов и торговые предпочтения. Резервная копия защищает дни или недели работы по настройке.

---

## Резервное копирование (Linux)

Резервные копии запускаются из терминала и по умолчанию выполняют **dry run** — они показывают, что будет скопировано, ничего не записывая, пока вы не добавите `--execute`:

```bash
# Посмотреть, что войдёт в резервную копию, ничего не записывая
wolfbot backup --install-root /opt/wolfbot --data-root /var/lib/wolfbot

# Реально записать архив резервной копии
wolfbot backup --install-root /opt/wolfbot --data-root /var/lib/wolfbot --execute
```

Добавьте `--label "before-weekend"`, чтобы пометить резервную копию узнаваемым именем. Итоговый архив записывается с ограниченными правами файла (доступен только вашему пользователю) вместе с квитанцией, описывающей его содержимое.

> Запустите `wolfbot backup --help` для полного актуального списка опций — флаги могут меняться между релизами.

### Windows

На Windows специальной команды резервного копирования пока нет — на данный момент безопаснее всего скопировать вашу папку данных WolfBot в надёжное место перед серьёзным изменением (см. [Troubleshooting](/docs/troubleshooting), если не знаете, где она).

## Восстановление из резервной копии

```bash
wolfbot restore-backup --install-root /opt/wolfbot --data-root /var/lib/wolfbot --backup <path-to-archive>
```

Как и резервное копирование, это по умолчанию dry run, чтобы вы могли увидеть, что изменится, прежде чем подтвердить через `--execute`. Используйте `wolfbot inspect-backup <path-to-archive>` сначала, если хотите просто проверить содержимое архива, ничего не восстанавливая.

---

## Что попадает в резервную копию

Ваша конфигурация, настройки стратегий, параметры риска и история торговли находятся в каталоге данных WolfBot и включаются в резервную копию. Секреты API брокеров обрабатываются осторожно — проверьте вывод `wolfbot backup` (даже в dry-run), если нужно подтвердить, что именно включает конкретный релиз, прежде чем полагаться на него при миграции машины.

---

## Миграция на новую машину

1. Создайте резервную копию на старой машине (`wolfbot backup ... --execute`)
2. Скопируйте полученный архив на новую машину
3. Установите WolfBot Community на новую машину
4. Восстановите архив (`wolfbot restore-backup ...`), затем проверьте аккаунты и настройки — заново введите любые API-ключи, которые не перенеслись

## Устранение неполадок

| Проблема | Решение |
|---|---|
| «Backup creation failed» | Проверьте дисковое пространство и что `--install-root`/`--data-root` указывают на реальные пути WolfBot |
| Восстановление выглядит неправильно после смены версии | Сначала обновите WolfBot до той же версии, на которой была сделана резервная копия, затем повторите |
| Не уверены, что резервная копия удалась | Запустите `wolfbot inspect-backup <path>`, чтобы проверить содержимое до того, как оно понадобится |
