# Value, Policy and Actor-Critic Methods for Trading

Algorithm choice should follow the trading decision, not fashion. A system choosing among hold, buy and sell has a different mathematical action space from one allocating weights across twenty instruments. Treating both as the same problem can create unstable learning, impossible orders or misleading benchmarks.

Reinforcement learning separates the environment, policy, reward and value estimate. Value-based, policy-based and actor-critic methods differ mainly in what they learn and how they improve behavior.

## Value-based methods

A value-based agent estimates how desirable an action is in a state, often through an action-value function:

```text
Q(s, a) = expected discounted return after action a in state s
```

It then selects the highest-valued available action, with an exploration rule during training. This maps naturally to small discrete choices such as hold/buy/sell or selecting one strategy from a fixed catalog.

The difficulty is combinatorics. If each of ten assets has five possible position changes, the joint action space becomes enormous. Discretizing position sizes also creates artificial jumps and may hide turnover. A value estimate can be highly optimistic when rare actions have little data.

## Policy-gradient methods

A policy method directly parameterizes the action distribution. It can output probabilities for discrete orders or parameters for continuous allocations. This is attractive when the action must express position size, target exposure or portfolio weights.

Policy gradients can optimize stochastic behavior but often have high-variance estimates. In trading, that variance is amplified by noisy rewards, serial dependence and a limited number of independent market regimes. Large updates can destroy previously useful behavior, which is why PPO's clipped objective is popular in research.

Continuous output is not automatically executable. A raw vector may violate leverage, minimum order size, cash or symbol constraints. Use a deterministic projection:

```text
raw policy action
-> normalize/project to admissible target
-> apply portfolio and account limits
-> convert target difference to orders
-> execute or reject with reason
```

## Actor-critic methods

An actor-critic system learns both a policy (actor) and a value estimate (critic). The critic estimates whether an action or state was better than expected; the actor uses that signal to update the policy. A2C, PPO and DDPG are members of this broad family, with different update and action-space assumptions.

The critic can reduce gradient variance, but a biased critic can steer the actor in the wrong direction. Shared data does not make their errors independent. Diagnose value loss, explained variance, action saturation and policy entropy alongside returns.

## Match method to decision geometry

Use discrete value methods when actions are few, mutually exclusive and operationally meaningful. Consider stochastic policy or actor-critic methods when allocation is continuous or exploration needs a distribution. Use hierarchical decisions when mixing time scales: one model selects a risk budget or strategy, while deterministic logic translates that choice into orders.

Never let the model encode broker mechanics implicitly. Tick size, quantity step, reduce-only semantics, hedging mode and margin checks belong to an execution adapter with explicit tests.

## On-policy and off-policy trade-offs

On-policy methods learn mainly from data generated by the current policy. They are conceptually clean but sample-hungry. Off-policy methods can reuse replay data from older behavior, improving sample efficiency while introducing distribution shift. Financial history cannot be resampled into new independent regimes, so replay volume should not be confused with independent evidence.

Record the behavior policy, action constraints and environment version for every transition. If the reward or fill model changes, old replay may no longer represent the current task.

## Evaluation matrix

Compare algorithms under identical conditions:

- the same chronological train/validation/test windows;
- the same observations and availability timestamps;
- the same transaction-cost and fill model;
- equal risk and exposure constraints;
- multiple seeds and complete hyperparameter logs;
- deterministic baselines and a no-trade baseline;
- stress tests for delayed fills, missing features and cost inflation.

Report turnover, concentration, drawdown, tail loss and rejected actions, not only cumulative return. A model with a higher backtest return but impossible order frequency is not the better policy.

## Safe WolfBot integration

The learned output should be a proposal with model version, observation cutoff, confidence diagnostics and intended target exposure. WolfBot's existing risk guards remain authoritative. If projection changes the action materially, log both raw and admissible targets so research can detect a policy that repeatedly asks for forbidden behavior.

Simulation and shadow mode should compare proposed actions with actual market outcomes without granting capital. Live promotion must cap account, symbol and strategy exposure and preserve a one-step rollback to the prior model.

## What research does not settle

No algorithm family is universally best for trading. PPO stability in one benchmark, DDPG performance on one continuous task or DQN success in a discrete simulator does not transfer automatically across assets, timeframes or execution venues. The action-space contract and evaluation discipline matter more than the acronym.
